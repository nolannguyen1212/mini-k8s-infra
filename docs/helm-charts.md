# 4. Helm: charting Postgres and Miniflux

Chapter 3 has two hand-written sets of YAML already, and every value that differs between dev/staging/prod (replica count, image tag, a database role's name) means editing YAML by hand or maintaining near-duplicate files. Helm is a templating and packaging layer: write the YAML once as a template with placeholders, supply different `values.yaml` per environment, render and apply.

## 4.1 Chart Postgres

```sh
mkdir -p charts/postgres/templates
```

`charts/postgres/Chart.yaml`:

```yaml
apiVersion: v2
name: postgres
description: Single shared PostgreSQL instance, one role+database per consuming app
type: application
version: 0.1.0
appVersion: "16"
```

`charts/postgres/values.yaml` generalizes chapter 3's hardcoded `miniflux` role into a list, so adding a second app later is a values change, not a template change:

```yaml
image:
  repository: postgres
  tag: "16-alpine"

storage: 5Gi

resources:
  requests: { cpu: 250m, memory: 256Mi }
  limits:   { cpu: 1, memory: 1Gi }

roles:
  - name: miniflux
    database: miniflux
    passwordSecretKey: MINIFLUX_DB_PASSWORD
```

`charts/postgres/templates/configmap.yaml` — the same script from chapter 3.1, now generated once per role:

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: {{ .Release.Name }}-init
data:
{{- range .Values.roles }}
  {{ .name }}-role.sh: |
    #!/bin/sh
    set -e
    psql -v ON_ERROR_STOP=1 --username "$POSTGRES_USER" -v rolepass="${{ .passwordSecretKey }}" <<-'EOSQL'
    SELECT format('CREATE ROLE {{ .name }} LOGIN PASSWORD %L', :'rolepass')
    WHERE NOT EXISTS (SELECT FROM pg_roles WHERE rolname = '{{ .name }}')\gexec
    SELECT 'CREATE DATABASE {{ .database }} OWNER {{ .name }}'
    WHERE NOT EXISTS (SELECT FROM pg_database WHERE datname = '{{ .database }}')\gexec
    REVOKE ALL ON DATABASE {{ .database }} FROM PUBLIC;
    EOSQL
{{- end }}
```

`${{ .passwordSecretKey }}` renders to a literal `$MINIFLUX_DB_PASSWORD` — Helm only replaces `{{ .passwordSecretKey }}`, the leading `$` is untouched text, expanded by the shell (not Helm) when the init container actually runs.

`charts/postgres/templates/statefulset.yaml` — chapter 3.1's StatefulSet, templated:

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: {{ .Release.Name }}
spec:
  serviceName: {{ .Release.Name }}
  replicas: 1
  selector:
    matchLabels: { app: {{ .Release.Name }} }
  template:
    metadata:
      labels: { app: {{ .Release.Name }} }
    spec:
      containers:
        - name: postgres
          image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
          ports:
            - containerPort: 5432
          env:
            - name: POSTGRES_USER
              value: postgres
          envFrom:
            - secretRef: { name: postgres-secret }
          volumeMounts:
            - { name: data, mountPath: /var/lib/postgresql/data, subPath: pgdata }
            - { name: init, mountPath: /docker-entrypoint-initdb.d }
          resources:
{{ toYaml .Values.resources | indent 12 }}
          readinessProbe:
            exec: { command: ["pg_isready", "-U", "postgres"] }
            initialDelaySeconds: 5
            periodSeconds: 5
      volumes:
        - name: init
          configMap:
            name: {{ .Release.Name }}-init
  volumeClaimTemplates:
    - metadata: { name: data }
      spec:
        accessModes: ["ReadWriteOnce"]
        resources: { requests: { storage: {{ .Values.storage }} } }
```

`charts/postgres/templates/service.yaml`:

```yaml
apiVersion: v1
kind: Service
metadata:
  name: {{ .Release.Name }}
spec:
  clusterIP: None
  selector: { app: {{ .Release.Name }} }
  ports:
    - port: 5432
```

Notice `postgres-secret` is referenced by a fixed name, not generated by this chart — chapter 3's Secret still exists as a separate object for now, chapter 6 changes how it gets there, not this chart.

```sh
helm lint charts/postgres
helm template postgres charts/postgres | less   # read it before trusting it
```

## 4.2 Chart Miniflux

```sh
mkdir -p charts/miniflux/templates
```

`charts/miniflux/Chart.yaml`:

```yaml
apiVersion: v2
name: miniflux
description: Miniflux RSS reader
type: application
version: 0.1.0
```

`charts/miniflux/values.yaml`:

```yaml
replicas: 1

image:
  repository: miniflux/miniflux
  tag: "latest"   # pin a real tag before this matters for real

host: miniflux.local

resources:
  requests: { cpu: 50m, memory: 64Mi }
  limits:   { cpu: 250m, memory: 128Mi }
```

`charts/miniflux/templates/deployment.yaml` — chapter 3.2's Deployment, templated:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ .Release.Name }}
spec:
  replicas: {{ .Values.replicas }}
  selector:
    matchLabels: { app: {{ .Release.Name }} }
  template:
    metadata:
      labels: { app: {{ .Release.Name }} }
    spec:
      containers:
        - name: miniflux
          image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
          imagePullPolicy: IfNotPresent
          ports:
            - { name: http, containerPort: 8080 }
          env:
            - { name: RUN_MIGRATIONS, value: "1" }
            - { name: CREATE_ADMIN, value: "1" }
          envFrom:
            - secretRef: { name: miniflux-secret }
          resources:
{{ toYaml .Values.resources | indent 12 }}
          readinessProbe:
            httpGet: { path: /healthcheck, port: 8080 }
            initialDelaySeconds: 5
            periodSeconds: 10
          livenessProbe:
            httpGet: { path: /healthcheck, port: 8080 }
            initialDelaySeconds: 15
            periodSeconds: 15
```

`charts/miniflux/templates/service.yaml`:

```yaml
apiVersion: v1
kind: Service
metadata:
  name: {{ .Release.Name }}
spec:
  selector: { app: {{ .Release.Name }} }
  ports:
    - { port: 80, targetPort: 8080 }
```

`charts/miniflux/templates/ingress.yaml`:

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: {{ .Release.Name }}
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  ingressClassName: nginx
  rules:
    - host: {{ .Values.host }}
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service: { name: {{ .Release.Name }}, port: { number: 80 } }
```

```sh
helm lint charts/miniflux
helm template miniflux charts/miniflux | diff - <(kubectl get deployment,service,ingress -n miniflux -o yaml) || true
```

That `diff` won't be clean (field ordering, generated metadata differ), but skimming it once is worth it: the rendered chart should describe the *same objects* chapter 3 applied by hand, just generated instead of typed.

## 4.3 Per-environment values, and the render/diff/install loop

`charts/miniflux/values-prod.yaml`:

```yaml
replicas: 2
image:
  tag: "2.1.0"
host: real-domain.example.com
resources:
  requests: { cpu: 100m, memory: 128Mi }
  limits:   { cpu: 500m, memory: 256Mi }
```

```sh
helm template miniflux charts/miniflux -f charts/miniflux/values-prod.yaml | grep -E "replicas|host:"
helm upgrade --install miniflux charts/miniflux -n miniflux
helm history miniflux -n miniflux
helm rollback miniflux 1 -n miniflux
```

`values.yaml` is the base, `-f` files layer on top and override matching keys, `--set key=value` wins over all files. `helm template` is the command to run every single time you change a template — pure client-side rendering, zero cluster interaction, the fastest feedback loop for catching a broken indent or wrong field name.

## 4.4 Try it

```sh
helm lint charts/postgres charts/miniflux
helm template postgres charts/postgres | grep -A2 "kind: StatefulSet"
helm template miniflux charts/miniflux | grep -A2 "kind: Deployment"
```

Neither chart is meant to be `helm install`-ed standalone from here on — chapter 5 hands both to Kustomize instead, which is how they actually reach a cluster from chapter 7 onward.
