# 9. Helm: charting everything

Chapter 8 has 8 hand-written YAML files already, and every value that differs between dev/staging/prod (replica count, image tag, a database role's name) means editing YAML by hand or maintaining near-duplicate files. Helm is a templating and packaging layer: write the YAML once as a template with placeholders, supply different `values.yaml` per environment, render and apply.

## 9.1 Chart Postgres

```sh
mkdir -p charts/postgres/templates
```

`charts/postgres/Chart.yaml`:

```yaml
apiVersion: v2
name: postgres
description: Single shared PostgreSQL instance, one role+database per consuming app
type: application
version: 0.1.0
appVersion: "16"
```

`charts/postgres/values.yaml` generalizes chapter 8's hardcoded `miniflux` role into a list, so adding a second app later (chapter 17) is a values change, not a template change:

```yaml
image:
  repository: postgres
  tag: "16-alpine"

storage: 5Gi

resources:
  requests: { cpu: 250m, memory: 256Mi }
  limits:   { cpu: 1, memory: 1Gi }

roles:
  - name: miniflux
    database: miniflux
    passwordSecretKey: MINIFLUX_DB_PASSWORD
```

`charts/postgres/templates/configmap-init.yaml` — the same script from chapter 8.2, now generated once per role:

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: {{ .Release.Name }}-init
data:
{{- range .Values.roles }}
  {{ .name }}-role.sh: |
    #!/bin/sh
    set -e
    psql -v ON_ERROR_STOP=1 --username "$POSTGRES_USER" -v rolepass="${{ .passwordSecretKey }}" <<-'EOSQL'
    DO $$
    BEGIN
      IF NOT EXISTS (SELECT FROM pg_roles WHERE rolname = '{{ .name }}') THEN
        CREATE ROLE {{ .name }} WITH LOGIN PASSWORD :'rolepass';
      END IF;
    END
    $$;
    SELECT 'CREATE DATABASE {{ .database }} OWNER {{ .name }}'
    WHERE NOT EXISTS (SELECT FROM pg_database WHERE datname = '{{ .database }}')\gexec
    REVOKE ALL ON DATABASE {{ .database }} FROM PUBLIC;
    EOSQL
{{- end }}
```

`${{ .passwordSecretKey }}` renders to a literal `$MINIFLUX_DB_PASSWORD` — Helm only replaces `{{ .passwordSecretKey }}`, the leading `$` is untouched text, expanded by the shell (not Helm) when the init container actually runs.

`charts/postgres/templates/statefulset.yaml` — chapter 8.2's StatefulSet, templated:

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: {{ .Release.Name }}
spec:
  serviceName: {{ .Release.Name }}
  replicas: 1
  selector:
    matchLabels: { app: {{ .Release.Name }} }
  template:
    metadata:
      labels: { app: {{ .Release.Name }} }
    spec:
      containers:
        - name: postgres
          image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
          ports:
            - containerPort: 5432
          env:
            - name: POSTGRES_USER
              value: postgres
          envFrom:
            - secretRef: { name: postgres-secret }
          volumeMounts:
            - { name: data, mountPath: /var/lib/postgresql/data, subPath: pgdata }
            - { name: init, mountPath: /docker-entrypoint-initdb.d }
          resources:
{{ toYaml .Values.resources | indent 12 }}
          readinessProbe:
            exec: { command: ["pg_isready", "-U", "postgres"] }
            initialDelaySeconds: 5
            periodSeconds: 5
      volumes:
        - name: init
          configMap:
            name: {{ .Release.Name }}-init
  volumeClaimTemplates:
    - metadata: { name: data }
      spec:
        accessModes: ["ReadWriteOnce"]
        resources: { requests: { storage: {{ .Values.storage }} } }
```

`charts/postgres/templates/service.yaml`:

```yaml
apiVersion: v1
kind: Service
metadata:
  name: {{ .Release.Name }}
spec:
  clusterIP: None
  selector: { app: {{ .Release.Name }} }
  ports:
    - port: 5432
```

Notice `postgres-secret` is referenced by a fixed name, not generated by this chart — chapter 8's Secret still exists as a separate object for now, chapter 11-12 change how it gets there, not this chart.

```sh
helm lint charts/postgres
helm template postgres charts/postgres | less   # read it before trusting it
```

`charts/miniflux/templates/deployment.yaml` — chapter 8.3's Deployment, templated:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ .Release.Name }}
spec:
  replicas: {{ .Values.replicas }}
  selector:
    matchLabels: { app: {{ .Release.Name }} }
  template:
    metadata:
      labels: { app: {{ .Release.Name }} }
    spec:
      containers:
        - name: miniflux
          image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
          imagePullPolicy: IfNotPresent
          ports:
            - { name: http, containerPort: 8080 }
          env:
            - { name: RUN_MIGRATIONS, value: "1" }
            - { name: CREATE_ADMIN, value: "1" }
          envFrom:
            - secretRef: { name: miniflux-secret }
          resources:
{{ toYaml .Values.resources | indent 12 }}
          readinessProbe:
            httpGet: { path: /healthcheck, port: 8080 }
            initialDelaySeconds: 5
            periodSeconds: 10
          livenessProbe:
            httpGet: { path: /healthcheck, port: 8080 }
            initialDelaySeconds: 15
            periodSeconds: 15
```

`charts/miniflux/templates/service.yaml`:

```yaml
apiVersion: v1
kind: Service
metadata:
  name: {{ .Release.Name }}
spec:
  selector: { app: {{ .Release.Name }} }
  ports:
    - { port: 80, targetPort: 8080 }
```

`charts/miniflux/templates/ingress.yaml`:

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: {{ .Release.Name }}
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  ingressClassName: nginx
  rules:
    - host: {{ .Values.host }}
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service: { name: {{ .Release.Name }}, port: { number: 80 } }
```

```sh
helm lint charts/miniflux
helm template miniflux charts/miniflux | diff - <(kubectl get deployment,service,ingress -n miniflux -o yaml) || true
```

That `diff` won't be clean (field ordering, generated metadata differ), but skimming it once is worth it: the rendered chart should describe the *same objects* chapter 8 applied by hand, just generated instead of typed.

## 9.3 Per-environment values, and the render/diff/install loop

`charts/miniflux/values-prod.yaml`:

```yaml
replicas: 2
image:
  tag: "2.1.0"
host: real-domain.example.com
resources:
  requests: { cpu: 100m, memory: 128Mi }
  limits:   { cpu: 500m, memory: 256Mi }
```

```sh
helm template miniflux charts/miniflux -f charts/miniflux/values-prod.yaml | grep -E "replicas|host:"
helm upgrade --install miniflux charts/miniflux -n miniflux
helm history miniflux -n miniflux
helm rollback miniflux 1 -n miniflux
```

`values.yaml` is the base, `-f` files layer on top and override matching keys, `--set key=value` wins over all files. `helm template` is the command to run every single time you change a template, pure client-side rendering, zero cluster interaction, the fastest feedback loop for catching a broken indent or wrong field name.

## 9.4 Redis, Kafka, MinIO — charted directly, ahead of any app needing them

Miniflux only needs Postgres. Redis, Kafka, and MinIO get built now anyway, as a shared platform layer any future app can use, so the pattern already exists the day something needs a cache, a queue, or object storage instead of being invented under pressure later. None of the three need a raw-manifest phase first, chapter 8 already covered the mechanics (StatefulSet, headless Service, `envFrom` for a password) on Postgres — repeating that by hand three more times would teach nothing new.


`charts/kafka/values.yaml`:

```yaml

  limits:   { cpu: "1", memory: 1Gi }

```

`charts/kafka/templates/statefulset.yaml` — single-broker KRaft mode, no ZooKeeper. `KAFKA_CONTROLLER_QUORUM_VOTERS=1@localhost:9093` works because broker and controller are the same process here, `localhost` never leaves the Pod's own network namespace. `KAFKA_ADVERTISED_LISTENERS` has to be the DNS name other Pods can actually resolve, a client handed `localhost` or a bare Pod IP by the broker's metadata response fails to connect even though the initial connection succeeded, a classic Kafka-in-Kubernetes gotcha:

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: {{ .Release.Name }}
spec:
  serviceName: {{ .Release.Name }}
  replicas: 1
  selector:
    matchLabels: { app: {{ .Release.Name }} }
  template:
    metadata:
      labels: { app: {{ .Release.Name }} }
    spec:
      containers:
        - name: kafka
          image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
          ports:
            - { containerPort: 9092, name: broker }
            - { containerPort: 9093, name: controller }
          env:
            - { name: CLUSTER_ID, value: {{ .Values.clusterId | quote }} }
            - { name: KAFKA_NODE_ID, value: "1" }
            - { name: KAFKA_PROCESS_ROLES, value: "broker,controller" }
            - { name: KAFKA_LISTENERS, value: "PLAINTEXT://:9092,CONTROLLER://:9093" }
            - { name: KAFKA_ADVERTISED_LISTENERS, value: "PLAINTEXT://kafka-0.kafka.platform.svc.cluster.local:9092" }
            - { name: KAFKA_CONTROLLER_LISTENER_NAMES, value: "CONTROLLER" }
            - { name: KAFKA_LISTENER_SECURITY_PROTOCOL_MAP, value: "CONTROLLER:PLAINTEXT,PLAINTEXT:PLAINTEXT" }
            - { name: KAFKA_CONTROLLER_QUORUM_VOTERS, value: "1@localhost:9093" }
            - { name: KAFKA_INTER_BROKER_LISTENER_NAME, value: "PLAINTEXT" }
            - { name: KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR, value: "1" }
            - { name: KAFKA_TRANSACTION_STATE_LOG_REPLICATION_FACTOR, value: "1" }
            - { name: KAFKA_TRANSACTION_STATE_LOG_MIN_ISR, value: "1" }
            - { name: KAFKA_AUTO_CREATE_TOPICS_ENABLE, value: "true" }
            - { name: KAFKA_HEAP_OPTS, value: {{ .Values.heapOpts | quote }} }
          volumeMounts:
            - { name: data, mountPath: /var/lib/kafka/data }
          resources:
{{ toYaml .Values.resources | indent 12 }}
          readinessProbe:
            tcpSocket: { port: 9092 }
            initialDelaySeconds: 15
            periodSeconds: 10
  volumeClaimTemplates:
    - metadata: { name: data }
      spec:
        accessModes: ["ReadWriteOnce"]
        resources: { requests: { storage: {{ .Values.storage }} } }
```

`charts/kafka/templates/service.yaml`:

```yaml
apiVersion: v1
kind: Service
metadata:
  name: {{ .Release.Name }}
spec:
  clusterIP: None
  selector: { app: {{ .Release.Name }} }
  ports:

    - { name: controller, port: 9093 }
```

No Secret for Kafka: it runs with no auth (no SASL/ACLs), acceptable only because chapter 14's NetworkPolicy restricts who can reach `platform` at all — revisit if this cluster ever becomes multi-tenant.

None of `redis`, `kafka`, `minio` can actually be `helm install`-ed usefully yet, `redis-secret`/`minio-secret` don't exist. `helm lint`/`helm template` remain the entire verification loop until chapter 12 gives these charts real secrets to consume.
